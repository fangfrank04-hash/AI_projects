# 页面交互逻辑说明文档

> 本文档详细解释：页面交互逻辑写在哪里？Skills、Python后台、MCP服务、Java服务各自承担什么任务？它们是如何协同工作的？

---

## 一、简短回答

具体来说：
- ✅ **React前端**（`react-frontend/src/App.jsx`）：负责页面交互（点击、输入、拖拽等）
- ⚠️ **Skills**（`proposal-python-v2/skills/`）：负责 AI Agent 的决策逻辑（如何响应用户输入）
- ⚠️ **Python后台**（`proposal-python-v2/`）：负责工具执行（调用Java接口）
- ⚠️ **Java后台**（`proposal-java/`）：负责数据操作（数据库CRUD）

---

## 二、三层逻辑分离

### 🍽️ 餐厅比喻

| 层级 | 餐厅角色 | 项目对应 | 负责内容 |
|------|----------|----------|----------|
| **UI层** | 服务员（点餐、上菜） | React前端（`App.jsx`） | 页面交互（点击、输入、拖拽） |
| **业务层** | 厨师长（决定怎么做菜） | Skills（`SKILL.md`） | AI决策（如何响应用户输入） |
| **工具层** | 采购员（买菜、切菜） | Python后台（`mcp_server/`） | 工具执行（调用Java接口） |
| **数据层** | 仓库（存储食材） | Java后台（`proposal-java/`） | 数据操作（数据库CRUD） |

### 🔧 具体决策逻辑（在 `SKILL.md` 中）

#### 1. 意图分析（SKILL.md 第33-57行）
```markdown
### 步骤1：意图分析

收到用户指令后，首先判断意图类型：

**类型A — 修改项目基本信息**
- 触发词：产品编号、产品名称、改成、修改产品、productNo、productName
- 字段白名单：只有 productNo 和 productName 可以修改
- 字段黑名单：项目名称(name)、部门(dept)、级别(level)等 → 拦截
- 拦截话术："💡 抱歉，系统规定除【产品编号】和【产品名称】外，其他项目基本信息不可在此修改。"
- 缺失关键信息时追问："请确认：您要将【哪个字段】修改为什么值？"

**类型B — 修改团队成员**
- 增成员触发词：新增、添加、加入、增加成员
- 删成员触发词：删除、移除、去掉成员
- 改角色触发词：角色改成、变更为、调整角色
- 改职责触发词：勾选、取消、增加职责、去掉职责
- 缺失关键信息时追问确认

**类型C — 日常对话**
- 触发词：你好、你是谁、介绍一下、帮助、能做什么、谢谢
- 处理：用自然、专业的语气回复，不调用任何工具

**类型D — 查看数据**
- 触发词：查看、显示、看看、当前、是什么、有哪些
- 处理：调用 get_project_info + get_team_members_list，整理后展示
```

#### 2. 执行流程（SKILL.md 第59-79行）
```markdown
### 步骤2：获取当前数据

- 调用 get_project_info(project_id) 获取最新项目信息
- 调用 get_team_members_list(project_id) 获取最新团队成员

### 步骤3：执行操作

根据意图类型执行对应操作：

- 修改产品编号 → update_project_info(project_id, productNo="新值")
- 修改产品名称 → update_project_info(project_id, productName="新值")

- 勾选职责 → update_member_duty(project_id, name="姓名", duty_name="职责名", checked=true)
- 取消职责 → update_member_duty(project_id, name="姓名", duty_name="职责名", checked=false)

### 步骤4：确认结果

- 操作成功后，告知用户具体改了什么
- 若用户指令不明确，追问确认后再执行
- 若工具返回失败，如实告知错误信息
```

```python
def call_java_api(service: str, method: str, params: dict) -> dict:
    """调用Java REST接口"""
    url = f"{Config.JAVA_BASE_URL}/portal/RestAction.invoke.do?url={service}/{method}"
    
    headers = {
        "Content-Type": "application/json",
        "Authorization": f"Bearer {Config.JAVA_AUTH_TOKEN}"
    }
    
    response = requests.post(url, json=params, headers=headers)
```

```java
@RequestMapping("/portal/RestAction.invoke.do")
public class PmProjectController {
    
    @Autowired

    public ResponseEntity<?> updateProjectInfo(@RequestBody Map<String, Object> params) {
        String projectId = (String) params.get("projectId");
        String productNo = (String) params.get("productNo");
        String productName = (String) params.get("productName");

        PmProject project = pmProjectService.updateProjectInfo(projectId, productNo, productName);

    }
```

#### 2. Service层（业务逻辑）
```java
@Service
public class PmProjectService {
    
    @Autowired
    private PmProjectDao pmProjectDao;
    
    public PmProject updateProjectInfo(String projectId, String productNo, String productName) {
        // 数据验证
        if (productNo != null && !productNo.isEmpty()) {
            // 更新产品编号
            pmProjectDao.updateProductNo(projectId, productNo);
        }
        
        if (productName != null && !productName.isEmpty()) {
            // 更新产品名称
            pmProjectDao.updateProductName(projectId, productName);
        }
        
        // 返回更新后的项目信息
        return pmProjectDao.getProjectById(projectId);
    }
}
```

## 九、常见问题解答

### Q1：为什么交互逻辑要写在前端，而不是后端？

**答案**：
- ✅ **前端负责UI交互**：点击、输入、拖拽等用户操作
- ✅ **后端负责业务逻辑**：数据处理、API调用等
- ✅ **前后端分离**：符合现代Web开发最佳实践

---

### Q2：Skills文件能不能直接操作数据库？

**答案**：
- ❌ **不能**。Skills文件只定义"怎么做"，不执行具体操作
- ✅ **MCP Server**才是执行层，负责调用Java接口
- ✅ **Java后台**才是数据层，负责数据库操作

---

### Q3：如果我想修改交互逻辑，应该改哪里？

**答案**：
- **修改页面显示** → 改 `react-frontend/src/App.jsx`
- **修改AI决策流程** → 改 `proposal-python-v2/skills/*/SKILL.md`
- **修改工具执行逻辑** → 改 `proposal-python-v2/mcp_server/http_server.py`
- **修改数据库操作** → 改 `proposal-java/src/main/java/com/example/dao/*Dao.java`
