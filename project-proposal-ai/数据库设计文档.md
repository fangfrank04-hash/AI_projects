# 数据库设计文档 - 项目方案书AI自动填写系统

## 一、设计概述

### 1.1 数据库选型

| 项目 | 选择 | 说明 |
|------|------|------|
| 数据库 | H2 Database | 嵌入式，无需安装，文件存储 |
| 模式 | 文件模式 | `jdbc:h2:file:./data/proposal_db` |
| ORM | JPA/Hibernate | 自动建表，简化开发 |

### 1.2 设计原则

1. **轻量化**：使用H2嵌入式数据库，无需独立数据库服务
2. **JSON存储**：部分灵活结构使用JSON字段存储（responsibilities、role_ids、data等）
3. **版本控制**：知识库规则支持版本管理
4. **审计追踪**：操作日志记录完整操作历史
5. **扩展性**：新增V3阶段活动、交付物、关联项目表，支持未来业务扩展

**表关系说明**：
- `projects` 1:N `team_members`（一个项目有多名团队成员）
- `projects` 1:1 `proposals`（一个项目对应一份方案书）
- `proposals` 1:N `proposal_steps`（一份方案书有5个步骤）
- `projects` 1:N `project_program_plans`（一个项目有多个阶段活动节点）
- `project_program_plans` 1:N `project_deliverables`（一个阶段活动关联多个交付物）
- `projects` 1:N `related_projects`（一个项目可关联多个其他项目）
- `projects` 1:N `history_records`（一个项目有多个历史快照）

## 三、表结构详细设计

### 3.1 项目表 (projects)

存储项目基本信息。对应Java实体 `Project.java`，接口 `findProjectById` / `updatePmProject`。

```sql
CREATE TABLE projects (
    id VARCHAR(50) PRIMARY KEY COMMENT '项目编号，如PJ-202603-S-068',
    name VARCHAR(200) NOT NULL COMMENT '项目名称',
    dept VARCHAR(100) COMMENT '立项申请部门',
    base_req VARCHAR(50) COMMENT '基准需求编号，如BD-2026-0078',
    level VARCHAR(10) CHECK (level IN ('S级', 'A级', 'B级', 'C级')) COMMENT '项目控制策略类型/项目级别',
    product_no VARCHAR(50) COMMENT '产品编号',
    product_name VARCHAR(200) COMMENT '产品名称',
    req_dept VARCHAR(100) COMMENT '需求提出部门',
    change_req VARCHAR(50) COMMENT '变更需求编号',
    pm_name VARCHAR(50) NOT NULL COMMENT '项目经理姓名',
    proposal_background TEXT COMMENT '方案编制背景',
    proposal_scope TEXT COMMENT '方案编制范围',
    status VARCHAR(20) DEFAULT '待确认' COMMENT '方案书状态：待确认/已确认',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '更新时间'
);

-- 索引
CREATE INDEX idx_projects_pm ON projects(pm_name);
CREATE INDEX idx_projects_level ON projects(level);
CREATE INDEX idx_projects_status ON projects(status);
CREATE INDEX idx_projects_dept ON projects(dept);
```

**对应JPA实体**：`Project.java`（`com.ccdc.proposal.entity.Project`）

---

### 3.2 项目团队成员表 (team_members)

存储项目团队成员及职责。对应Java实体 `TeamMember.java`，接口 `findPmProjectMemberList` / `createPmProjectMembers` / `deletePmProjectMembers` / `updateMemberRoles` / `updateDuty`。

```sql
CREATE TABLE team_members (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '自增ID',
    project_id VARCHAR(50) NOT NULL COMMENT '项目ID',
    role VARCHAR(50) NOT NULL COMMENT '项目角色，如产品经理、项目经理、开发负责人、测试负责人',
    name VARCHAR(50) NOT NULL COMMENT '人员姓名',
    user_id VARCHAR(50) COMMENT '[新增] 用户ID，对应系统用户表，用于createPmProjectMembers中的userIds参数',
    nickname VARCHAR(50) COMMENT '[新增] 昵称，用于findPmProjectMemberList中的nickname参数',
    role_ids TEXT COMMENT '[新增] 角色ID列表，JSON格式，用于updateMemberRoles中的roleIds参数，如["132969","136823"]',
    responsibilities TEXT COMMENT '职责列表，JSON格式：[{"name":"产品发布","checked":true}]',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE
);

-- 索引
CREATE INDEX idx_team_project ON team_members(project_id);
CREATE INDEX idx_team_name ON team_members(name);
CREATE INDEX idx_team_user_id ON team_members(user_id);
CREATE INDEX idx_team_nickname ON team_members(nickname);
```

**responsibilities JSON结构**：
```json
[
  {"name": "产品发布", "checked": true},
  {"name": "业务方案可行性分析", "checked": true},
  {"name": "项目立项", "checked": true}
]
```

**role_ids JSON结构**：
```json
["132969", "136823"]
```

**对应JPA实体**：`TeamMember.java`（`com.ccdc.proposal.entity.TeamMember`）

### 3.3 方案书表 (proposals)

存储方案书整体状态和流程信息。对应Java实体 `Proposal.java`。

```sql
CREATE TABLE proposals (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '自增ID',
    project_id VARCHAR(50) NOT NULL UNIQUE COMMENT '项目ID',
    current_step INT DEFAULT 1 COMMENT '当前步骤：1-5',
    completed_steps VARCHAR(50) COMMENT '已完成步骤，JSON数组：[1,2,3]',
    status VARCHAR(20) DEFAULT '待确认' COMMENT '状态：待确认/已确认',
    confirmed_by VARCHAR(50) COMMENT '确认人',
    confirmed_at TIMESTAMP COMMENT '确认时间',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '更新时间',
    FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE
);

-- 索引
CREATE INDEX idx_proposal_project ON proposals(project_id);
CREATE INDEX idx_proposal_status ON proposals(status);
```

**completed_steps示例**：
```json
[1, 2, 3]
```

**对应JPA实体**：`Proposal.java`（`com.ccdc.proposal.entity.Proposal`）

### 3.4 方案书步骤数据表 (proposal_steps)

存储方案书各步骤的详细数据。对应Java实体 `ProposalStep.java`。

```sql
CREATE TABLE proposal_steps (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '自增ID',
    proposal_id BIGINT NOT NULL COMMENT '方案书ID',
    step_number INT NOT NULL COMMENT '步骤编号：1-5',
    step_name VARCHAR(50) NOT NULL COMMENT '步骤名称',
    data TEXT NOT NULL COMMENT '步骤数据，JSON格式',
    status VARCHAR(20) DEFAULT '草稿' COMMENT '状态：草稿/已确认',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '更新时间',
    FOREIGN KEY (proposal_id) REFERENCES proposals(id) ON DELETE CASCADE,
    UNIQUE (proposal_id, step_number)
);

-- 索引
CREATE INDEX idx_step_proposal ON proposal_steps(proposal_id);
CREATE INDEX idx_step_number ON proposal_steps(step_number);
```

**步骤与数据结构对应**：

| step_number | step_name | data JSON结构 |
|-------------|-----------|---------------|
| 1 | 项目团队职责 | teamData数组 |
| 2 | 管控方案 | controlData数组 |
| 3 | 进度计划 | scheduleData数组 |
| 4 | 资源计划 | resourceData对象 |
| 5 | 质量保证计划 | qualityData对象 |

**对应JPA实体**：`ProposalStep.java`（`com.ccdc.proposal.entity.ProposalStep`）

### 3.8 阶段活动表 (project_program_plans) [V3使用]

存储项目阶段活动计划树。支持树形结构（parent_id）。对应接口 `findProjectProgramPlanTreeByProjectId` / `savePlanTaskCutResult`。

```sql
CREATE TABLE project_program_plans (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '自增ID',
    project_id VARCHAR(50) NOT NULL COMMENT '项目ID',
    task_no VARCHAR(50) COMMENT '任务编号',
    task_name VARCHAR(200) NOT NULL COMMENT '任务名称',
    phase VARCHAR(50) COMMENT '阶段名称，如需求阶段、开发阶段、测试阶段',
    required BOOLEAN DEFAULT TRUE COMMENT '是否必选',
    cut_result VARCHAR(20) COMMENT '裁剪结果：执行/裁剪/部分裁剪',
    cut_result_explain TEXT COMMENT '裁剪结果说明',
    parent_id BIGINT COMMENT '父节点ID，支持树形结构，根节点为NULL',
    sort_order INT DEFAULT 0 COMMENT '同级排序号',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '更新时间',
    FOREIGN KEY (project_id) REFERENCES projects(id) ON DELETE CASCADE,
    FOREIGN KEY (parent_id) REFERENCES project_program_plans(id) ON DELETE CASCADE
);

-- 索引
CREATE INDEX idx_plan_project ON project_program_plans(project_id);
CREATE INDEX idx_plan_parent ON project_program_plans(parent_id);
CREATE INDEX idx_plan_sort ON project_program_plans(sort_order);
```

**对应JPA实体**：暂无（V3阶段由Python MCP工具直接访问）

### 7.2 数据流说明

```
┌─────────────────┐     MCP工具调用      ┌─────────────────┐
│  Python MCP服务  │ ◄─────────────────► │   H2 Database   │
│  (FastMCP)       │                     │                 │
└─────────────────┘                     │  projects       │
        │                               │  team_members   │
        │ 读写操作                         │  proposals      │
        ▼                               │  proposal_steps │
┌─────────────────┐                     │  knowledge_rules│
│  proposal-java   │                     │  history_records│
│  (RestAction     │                     │  operation_logs │
│   Controller)    │                     │  project_program│
└─────────────────┘                     │    _plans       │
                                        │  project_deliver│
                                        │    ables        │
                                        │  related_project│
                                        │    s            │
                                        └─────────────────┘
```

- **Java层**：通过 `RestActionController` 调用MCP工具，MCP Server直接操作H2数据库
- **Python层**：MCP Server提供工具定义，接收前端（或Java代理）调用，执行SQL
- **新增V3表**：由Python MCP Server直接管理，Java层通过MCP工具间接访问

## 八、备份与恢复

### 8.1 H2数据库文件位置

```
项目目录/
└── data/
    ├── proposal_db.mv.db      # 主数据文件
    └── proposal_db.trace.db   # 跟踪日志（可选）
```

### 8.2 备份命令

```bash
# 使用H2的Script工具备份
java -cp h2.jar org.h2.tools.Script \
    -url jdbc:h2:file:./data/proposal_db \
    -user sa \
    -script backup.sql

# 或使用文件复制（需停止服务）
cp data/proposal_db.mv.db backup/proposal_db_$(date +%Y%m%d).mv.db
```

```bash
# 使用RunScript工具恢复

```

## 九、性能优化建议

1. **索引优化**：已为常用查询字段建立索引
2. **缓存策略**：知识库规则可缓存（变化频率低）
3. **分页查询**：历史记录列表和交付物列表需要分页
4. **JSON查询**：H2支持JSON函数，可优化JSON字段查询

```sql
-- H2 JSON查询示例
SELECT * FROM proposal_steps
WHERE JSON_VALUE(data, '$.teamData[0].role') = '产品经理';

-- 按role_ids查询团队成员（H2 JSON语法）
SELECT * FROM team_members
WHERE JSON_CONTAINS(role_ids, '"132969"');
```
