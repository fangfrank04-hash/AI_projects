## 一、需求概述

### 1.1 业务背景

一体化项目与架构管理平台前期已完成一期和二期建设，于2025年上线多批次优化，并实现了信创改造，在需求、项目、架构、数据标准、IT知识产权等维度实现了全面推广使用。

随着各领域制度要求和使用体验反馈，为进一步增强平台整体服务能力，全面提升用户使用效率，拟基于大模型技术增加**项目方案书自动填写及检查**功能。

### 1.2 项目目标

在现有平台（Java + React）基础上，增加AI聊天机器人，辅助项目经理自动填写项目方案书，实现：
- 项目团队职责自动分配
- 管控方案自动裁剪
- 进度计划自动计算
- 资源计划自动分配
- 质量保证计划自动生成
- 方案书内容自动检查

**预期效果**：原本需要2小时的方案书填写，缩短至15分钟。

### 1.3 需求来源

金科公司 - 2026年四季度优化需求

## 二、用户角色与权限

| 角色 | 职责 | 权限 |
|------|------|------|
| **项目经理(PM)** | 负责项目整体管理 | 维护团队信息、启动AI填写、确认各步骤、一键回填 |
| **项目成员** | 参与项目执行 | 查看方案书、无编辑权限 |
| **系统管理员** | 维护知识库规则 | 配置项目级别规则、查看操作日志 |

**关键权限规则**：
- 只有项目经理可以操作AI聊天机器人
- 非项目经理打开方案书页面时，AI聊天入口隐藏或显示"仅项目经理可操作"
- 所有AI生成操作需校验Token有效性

## 三、功能需求

### 3.1 AI聊天机器人入口

**需求编号**：FR-001  
**功能描述**：在【项目实施管理 - 项目方案书】页面右下角，新增聊天机器人悬浮入口。  
**交互细节**：
- 入口为圆形悬浮按钮，带机器人图标
- 点击后弹出聊天对话框（支持拖拽移动位置）
- 对话框支持最大化/最小化
- 刷新页面后对话框状态保持（通过localStorage）

### 3.2 聊天机器人基础交互

**需求编号**：FR-002  
**功能描述**：聊天对话框弹出后，机器人主动发送问候信息。  
**交互流程**：
```
机器人首次问候：
"您好，{项目经理姓名}！我是您的AI项目助手。
正在检查项目信息..."

[若项目信息或团队信息未维护]
→ "检测到项目团队信息未完善，请先维护项目团队后再开始方案书填写。"
→ 提供【去维护团队】快捷按钮

[若信息已维护完整]
→ "✅ 检测到项目及团队信息已维护完整
即将开始【自动填写分模块确认流程】"
→ 自动开始步骤1
```

### 3.3 核心功能：5步自动填写流程

**需求编号**：FR-003  
**功能描述**：采用**分模块确认、分步回填**方式，依次完成5个模块的自动填写。

#### 填写模块清单

| 步骤 | 模块名称 | 优先级 | 说明 |
|------|----------|--------|------|
| 1 | 项目团队职责 | P0 | AI根据项目级别自动分配各角色职责 |
| 2 | 管控方案 | P0 | AI根据研发工艺要求及项目级别判断可裁剪阶段 |
| 3 | 项目进度计划 | P0 | AI根据立项批复日和项目周期计算里程碑 |
| 4 | 项目资源计划 | P0 | AI根据工作量数据分配到各成员 |
| 5 | 质量保证计划 | P0 | AI根据项目级别生成质量目标、评审机制、测试策略 |

#### 3.3.1 步骤1：项目团队职责确认

**需求编号**：FR-003-1

**前置条件**：项目团队信息已维护（至少包含角色和人员）。

**流程**：
1. 机器人读取当前项目的基础信息（项目编号、名称、级别、部门等）
2. 调取知识库中的公司规章制度（S/A/B/C级项目的团队职责标准）
3. 调取该用户历史填写的项目方案书数据作为参考
4. AI生成项目团队职责分配表
5. 在聊天对话框内展示预览卡片（表格形式，支持直接编辑）
6. 用户确认无误后，点击【一键回填】，将团队职责回填至项目方案书对应位置
7. 回填完成后，自动进入步骤2

**预览卡片字段**：
| 字段 | 说明 | 可编辑 |
|------|------|--------|
| 序号 | 自增 | 否 |
| 角色 | 产品经理、项目经理、架构师等 | 是 |
| 人员 | 具体姓名 | 是 |
| 职责 | 该角色的具体职责描述 | 是 |

**用户可输入指令示例**：
- "给产品经理增加需求分析职责"
- "把测试负责人的职责改一下"
- "增加安全评审职责"

#### 3.3.2 步骤2：管控方案确认

**需求编号**：FR-003-2

**前置条件**：步骤1已完成回填。

**流程**：
1. 机器人根据研发工艺要求及用户历史填写记录，生成管控方案
2. 根据项目级别判断可裁剪的阶段
3. 被裁剪的阶段，其"裁剪说明"字段默认填写"不涉及"
4. 在聊天对话框内展示管控方案预览卡片
5. 用户确认/编辑后，点击【一键回填】
6. 回填完成后，自动进入步骤3

**强制拦截规则**：
- **开发阶段**：不可裁剪（所有级别项目都必须执行）
- **测试阶段**：不可裁剪（所有级别项目都必须执行）
- 其余阶段根据级别规则判断是否可裁剪

**预览卡片字段**：
| 字段 | 说明 | 可编辑 |
|------|------|--------|
| 阶段名称 | 需求分析、项目评审、开发、测试、结项等 | 否 |
| 执行结果 | 执行 / 裁剪 | 是（受强制拦截规则限制） |
| 裁剪说明 | 若裁剪，填写原因 | 是 |

**用户可输入指令示例**：
- "裁剪项目评审阶段"
- "把需求分析改回执行"
- "所有阶段都执行"

#### 3.3.3 步骤3：项目进度计划确认

**需求编号**：FR-003-3

**前置条件**：步骤2已完成回填。

**流程**：
1. 机器人提示用户输入：
   - **立项批复日**（日期格式：YYYY-MM-DD）
   - **项目周期**（如：3个月、90天）
2. 用户提交后，AI根据项目级别和管控方案中的阶段，自动计算各里程碑时间节点
3. 在聊天对话框内展示进度计划预览卡片
4. 用户确认/编辑后，点击【一键回填】
5. 回填完成后，自动进入步骤4

**预览卡片字段**：
| 字段 | 说明 | 可编辑 |
|------|------|--------|
| 里程碑 | 需求评审完成、开发完成、测试完成、项目结项等 | 否 |
| 计划开始日期 | YYYY-MM-DD | 是 |
| 计划结束日期 | YYYY-MM-DD | 是 |

**用户可输入指令示例**：
- "把开发阶段延长到30天"
- "立项批复日改成2026-06-01"
- "重新计算里程碑"

#### 3.3.4 步骤4：项目资源计划填写与确认

**需求编号**：FR-003-4

**前置条件**：步骤3已完成回填。

**流程**：
1. 机器人提示用户输入以下核心数据：
   - **总工作量**（人天）
   - **总工期**（天）
   - **自有人员工作量**（人天）
   - **人员外包工作量**（人天）
   - **项目外包工作量**（人天）
2. 用户提交后，AI结合用户历史项目方案书数据及项目团队信息，生成"参与人员"中自有人员等相关信息
3. 在聊天对话框内展示资源计划预览卡片
4. 用户确认/编辑后，点击【一键回填】
5. 回填完成后，自动进入步骤5

**预览卡片字段**：
| 字段 | 说明 | 可编辑 |
|------|------|--------|
| 总工作量 | 单位：人天 | 是 |
| 总工期 | 单位：天 | 是 |
| 自有人员工作量 | 人天 | 是 |
| 人员外包工作量 | 人天 | 是 |
| 项目外包工作量 | 人天 | 是 |
| 参与人员明细 | 角色、姓名、工作量分配 | 是 |

**用户可输入指令示例**：
- "把自有人员工作量改成60"
- "增加一个架构师"
- "重新分配工作量"

#### 3.3.5 步骤5：质量保证计划确认

**需求编号**：FR-003-5

**前置条件**：步骤4已完成回填。

**流程**：
1. AI根据项目级别生成质量目标、评审机制、测试策略
2. **S级项目**：包含安全测试、最严格的质量目标
3. **B/C级项目**：可适当裁剪部分测试环节
4. 在聊天对话框内展示质量保证计划预览卡片
5. 用户确认/编辑后，点击【一键回填】
6. 回填完成后，机器人发送完成提示

**预览卡片字段**：
| 字段 | 说明 | 可编辑 |
|------|------|--------|
| 质量目标 | 缺陷密度、测试覆盖率等 | 是 |
| 评审机制 | 需求评审、设计评审、代码评审 | 是 |
| 测试策略 | 单元测试、集成测试、系统测试、安全测试 | 是 |
| 风险控制措施 | 风险识别和应对方案 | 是 |

**用户可输入指令示例**：
- "增加性能测试"
- "把测试覆盖率改成90%"
- "增加代码审查环节"

### 3.4 一键回填功能

**需求编号**：FR-004

**功能描述**：每个步骤的预览界面下方设置【一键回填】按钮。  
**规则**：
- 用户点击后，预览界面中的所有内容自动回填至【项目方案书】主页面对应字段
- 回填后立即保存到数据库
- 回填成功后，前端主页面数据实时刷新
- 支持步骤间跳转回填（如从步骤5跳转回步骤2重新回填）

### 3.5 项目团队维护提醒

**需求编号**：FR-005

**功能描述**：若项目经理未维护项目团队信息，机器人主动发送提醒。  
**交互**：
```
机器人："检测到项目团队信息尚未维护，请先完成团队信息维护后再进行方案书自动填写。"
【去维护团队】按钮 → 跳转至项目团队维护页面
```

### 3.6 智能对话与指令修改

**需求编号**：FR-006

**功能描述**：在每个步骤的预览卡片展示期间，用户可通过聊天框输入自然语言指令，指导机器人对预览内容进行调整。  
**规则**：
- 指令仅影响当前步骤的预览内容（草稿状态）
- 指令修改后，预览卡片实时更新
- 用户可多次输入指令，直到满意后确认
- 支持指令示例提示（输入框placeholder动态变化）

### 3.7 检查功能（标题所含）

**需求编号**：FR-007

**功能描述**：在5个模块全部回填完成后，机器人自动执行方案书完整性检查。  
**检查项**：
| 检查项 | 说明 |
|--------|------|
| 必填字段完整性 | 检查所有必填字段是否已填写 |
| 逻辑一致性 | 检查进度计划日期是否合理、资源计划工作量是否匹配 |
| 级别合规性 | 检查S级项目是否包含安全测试等强制要求 |
| 数据格式 | 检查日期格式、数字格式等 |

**检查结果展示**：
```
🤖 方案书检查报告
✅ 必填字段完整性：通过
✅ 逻辑一致性：通过
⚠️ 级别合规性：警告 - S级项目建议增加性能测试

```

### 5.2 数据流说明

**选项B（Java主导）**：
```
用户点"生成团队职责"
  ↓
前端调 Java：POST /api/project/{id}/ai/generate/team
  ↓
Java 从数据库读取：项目信息 + 团队信息 + 知识库规则 + 历史数据
  ↓
Java 组装请求，调 Python：POST /ai/generate/team-responsibilities
  请求体包含所有需要的数据（Python不读数据库）
  ↓
Python 调 LLM 生成内容
  ↓
Python 返回生成的团队职责 JSON
  ↓
Java 校验数据，存到数据库
  ↓
Java 返回给前端
  ↓
前端展示预览卡片
```

**关键原则**：
- **Python不碰数据库**：Python只接收Java传来的数据，调LLM生成，返回结果
- **Python不调Java**：Python是纯服务，被动等待Java调用
- **前端不调Python**：前端只和Java通信

## 九、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|----------|
| LLM响应不稳定 | 高 | 增加重试机制（最多3次），超时降级返回提示 |
| LLM生成格式错误 | 中 | JSON Schema校验，格式错误时重试 |
| 知识库规则变化 | 中 | YAML配置化，支持热更新 |
| Python服务宕机 | 高 | Java层增加熔断，返回"AI服务暂时不可用" |
| 历史数据不足 | 低 | 允许空历史，依赖知识库规则 |
