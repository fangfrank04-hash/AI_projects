# 打包操作清单（代码 1.2.0，照着做即可）

> 结论先记住：**这次依赖没变，1.4GB 的基础镜像 tar 不用重新构建，直接用旧的**。
> 你要做的只是把新的代码包传到内网。总共两样东西：旧 tar（如果内网已加载过就不用再传）+ 新 code/。

## 一、先在外网机器上确认（5 分钟）

```powershell
# 1. 确认测试和代码规范都是绿的（应输出 56 passed 和 All checks passed）
uv run pytest tests/ -q
uv run ruff check .

# 2. 确认代码副本同步测试通过（deploy_split/code 与 app 一致）
uv run pytest tests/test_deploy_sync.py -q
```

## 二、要传到内网的东西

| 顺序 | 内容 | 大小 | 说明 |
|---|---|---|---|
| 1 | `deploy_split/aiproctor_base_1.1.0.tar` | 1.4GB | **旧 tar 直接复用**。如果内网服务器已经 `docker load` 过一次，这项可以跳过 |
| 2 | `deploy_split/code/` 整个文件夹 | 约 13MB | 已包含 1.2.0 的全部新代码（黑屏检测等） |
| 3 | `deploy_split/docker-compose.yml`、`.env.example`、两份部署文档 | 几 KB | 一起拷上 |

> 为什么旧 tar 能用？基础镜像里只有 Python + 依赖库，没有业务代码。
> 这次所有改动都在代码层，`pyproject.toml`/`uv.lock` 的依赖一个字没动。
> 什么时候才要重建 tar？——你新增/升级了 Python 依赖库的时候（重建命令见文末）。

## 三、内网服务器上的操作

```bash
cd /opt/aiproctor   # 你的部署目录（按实际路径）

# 1. 首次才需要：加载基础镜像（如果之前加载过，跳过）
docker load -i aiproctor_base_1.1.0.tar

# 2. 用新的 code/ 覆盖旧的 code/ 文件夹

# 3. 重启容器（代码是挂载进去的，重启即生效，不碰镜像）
docker compose restart

# 4. 验证（三个都通过就 OK）
curl http://127.0.0.1:8000/ping    # 期望 {"pong":true,...}
curl http://127.0.0.1:8000/test    # 期望 {"code":200,...}
docker compose logs --tail 20      # 看启动日志无报错
```

## 四、验证黑屏新功能（可选）

上传一张全黑的图片，期望返回 `exception_code=1001`：

```bash
curl -X POST http://127.0.0.1:8000/upload_face -F "user_id=test001" -F "file=@黑屏图片.jpg"
# 期望 data 里：warning=true, action_type=black_screen, exception_code=1001, notify=true
# 同一 user_id 再传一张黑屏图：notify 应变为 false（去重生效）
```

## 五、以后什么时候要重建基础镜像

只有当 `pyproject.toml` 或 `uv.lock` 变了（加/删/升级依赖库）才需要：

```bash
docker build -t aiproctor-base:1.2.0 -f Dockerfile.base .
docker save -o aiproctor_base_1.2.0.tar aiproctor-base:1.2.0
# 同时把 deploy_split/docker-compose.yml 里的 image 改成新 tag
```

## 常见坑

- **改完代码必须 `docker compose restart`**，光改文件不重启不生效
- **不要改 compose 的挂载方式**（app/assets/models 三个子目录挂载是为了避开镜像里的 .venv）
- 传 code/ 时确认覆盖完整，别漏了 `models/` 里的 .task 模型文件
