# AI 监考服务 内网部署步骤 —— 分离模式（环境镜像 + 代码分开）

> 本文件夹（deploy_split）就是完整交付物：
> 1. `aiproctor_base_1.1.0.tar` —— **环境镜像**（Python 3.12.9 + 全部依赖，**不含代码**）
> 2. `code/` —— **代码包**（app 业务代码 + 必需资源 + AI 模型，约 13MB）
> 3. `docker-compose.yml` —— 启动配置（负责把 code/ 挂载进容器，已配好多进程）
>
> 分离模式的优势：**以后改代码只需替换 code/ 里的文件并重启，不用重拷 2GB 镜像**。

## 一、首次部署（内网服务器）

把整个 `deploy_split` 文件夹拷到内网服务器，例如 `/opt/aiproctor/`，保持结构：

```
/opt/aiproctor/
├── aiproctor_base_1.1.0.tar
├── .env.example
├── docker-compose.yml
└── code/
    ├── app/       ← 业务代码
    ├── assets/    ← 字体、离线文档页、自测图
    └── models/    ← AI 模型（.task 文件）
```

然后执行：

```bash
cd /opt/aiproctor

# 1. 加载环境镜像（只需做这一次）
docker load -i aiproctor_base_1.1.0.tar

# 2. 可选：需要调整识别阈值时复制配置模板并修改
cp .env.example .env

# 3. 启动（compose 会自动把 code/ 挂载进容器）
docker compose up -d

# 4. 验证
curl http://127.0.0.1:8000/ping     # 期望 {"pong":true,...}
curl http://127.0.0.1:8000/test     # 期望 {"code":200,...}
```

## 二、以后更新代码（分离模式的精髓）

```bash
# 1. 把新的 code/ 文件夹拷过来，覆盖旧的（或只覆盖改动的文件）
# 2. 重启容器即可，不碰镜像：
docker compose restart
```

只有当 **依赖变了**（pyproject.toml/uv.lock 有改动，比如新增了 Python 库）才需要
重新构建并拷贝新的环境镜像 tar。

## 三、Java 对接信息

- 接口：`POST http://<服务器IP>:8000/upload_face`，multipart 表单，字段 `user_id`（必传）和 `file`（图片）（同步返回，建议客户端超时 10~30 秒）
- 可选参数（不传 = 用默认值，每个都可单独传）：
  | 表单字段 | 默认 | 含义 |
  |---|---:|---|
  | max_left_angle | 6 | 左右角 > 该值 → 向左看 |
  | max_right_angle | -6 | 左右角 < 该值 → 向右看 |
  | max_up_angle | 6 | 上下角 > 该值 → 向上看 |
  | max_down_angle | -0.5 | 上下角 < 该值 → 向下看 |
- 响应：`{"code":200,"message":"识别成功","data":{"user_id":"user001","warning":bool,"action_type":"...","action_label":"...","exception_code":null,"exception_message":null,"notify":false}}`；黑屏时 `exception_code=1001`，连续黑屏仅首次 `notify=true`
- 去重状态仅保存在单个 Uvicorn 进程内；当前不引入 Redis，所以 `workers=2` 时两个进程可能各自首次提示一次
- 健康检查：`GET /ping` 返回含 `pool_ready`/`pool_size`（模型池就绪状态，探活用）
- 在线接口文档（离线可用）：`http://<服务器IP>:8000/docs`
- 告警归并表/负载均衡/调优：见同目录《高并发部署指南.md》第五、六节

## 注意事项

- **不要把整个 /app 挂载覆盖**：镜像内 `/app/.venv` 是 Python 运行环境，compose 里
  按 app/assets/models 三个子目录挂载就是为了避开它，别改动挂载方式。
- code/ 里的文件在容器运行时是"实时生效"的挂载，但改完必须 `docker compose restart`
  才会重新加载 Python 代码。
