# 视线偏移规则优化设计

## 背景

当前严格标准答案包含 305 张照片。基线总体通过率为 80.33%，其中正常考试 37/37、视线偏移 43/68。业务要求优先保护正常考试不误报，并明确以下行为都属于视线偏移：低头写字、低头看手机、坐着转头、坐着转身。

本轮只使用现有 MediaPipe 模型、现有照片和规则，不增加模型，不补拍照片，也不同时修改多人、伸胳膊或并发逻辑。

## 目标

1. 将已经识别为 `turn_body` 的坐着转身从离开座位改为视线偏移。
2. 在正常考试仍保持 37/37 的前提下，保守改善被判为正常考试的低头和转头照片。
3. 每一步独立验证并独立提交，避免多条规则同时变化导致结果不可解释。

## 非目标

- 不处理多人、伸胳膊、打电话和并发性能。
- 不增加 YOLO 或其他模型。
- 不把 305 张同场景照片的结果描述为生产环境准确率。
- 不为了提高总体分数接受任何正常考试误报。

## 设计

### 第一步：修正坐着转身的业务分类

`ImageProctor._check_pose_actions()` 已能通过双肩距离识别 `turn_body`。当前错误发生在识别后的业务归类，而不是模型漏检。因此保留识别条件和 `ActionType.TURN_BODY`，只把它的中文标签改为视线偏移，并在验证脚本中将 `turn_body` 映射到“视线偏移”。

这样既保留了机器可读的动作子类型，也让业务大类符合已确认规则。当前报告中 11 个 `turn_body` 全部来自预期为视线偏移的照片，没有预期为离开座位的样本依赖旧映射。

预期结果：视线偏移从 43/68 提升到至少 54/68，总体从 245/305 提升到至少 256/305，正常考试仍为 37/37。

### 第二步：保守优化低头和转头

先为原始头部姿态计算结果增加可测试的纯判断方法，使“角度计算”和“是否告警”分开。随后基于现有 305 张照片评估候选边界，每次只调整一个方向的默认边界。

候选规则必须同时满足：

- 37 张正常考试全部仍判为正常考试。
- 视线偏移通过数高于第一步结果。
- 离开座位、多人、打电话、伸胳膊的通过数不下降。
- 自定义接口角度参数仍能按单次请求覆盖默认值，且不会污染后续请求。

现有诊断显示，正常照片的头部计算值与部分异常照片存在重叠，因此不采用一次性大幅收紧全部方向的做法。若没有满足护栏的边界，第二步保留第一步成果，不强行修改阈值。

## 判断流程

单张照片仍按现有顺序处理：多人优先，其次 Pose 动作，再处理无人脸/无人，最后使用头部姿态判断。唯一的流程变化是 `turn_body` 命中后对外仍返回该动作子类型，但业务报告归为视线偏移。

头部姿态优化不改变 API 请求和响应结构，不新增持久状态，也不改变模型池和锁。

## 测试与验收

1. 单元测试证明 `turn_body` 的动作子类型不变、标签和报告大类改为视线偏移。
2. 使用已确认的坐着转身真实照片做行为测试。
3. 每个候选头部规则先写失败测试，再做最小实现。
4. 运行全部单元测试和 Ruff。
5. 运行严格 305 张验证，检查各类别数量和正常考试误报。
6. 只有满足全部护栏的改动才保留；否则撤销该候选规则，保留已通过的分类修正。

## 风险控制

- 分类修正不改变检测灵敏度，风险低。
- 头部边界调整容易误伤正常侧坐，因此正常考试 37/37 是硬性门槛，不以总体准确率抵消。
- 当前测试照片来自有限场景，结果只作为内部回归依据，不代表陌生考场或生产环境表现。
