# 配置可靠性改造设计

## 背景

项目文档声称所有检测阈值都能通过 `.env` 调整，但当前实现存在三类漂移：

1. `app/core/config.py` 只读取进程环境变量，不会读取项目根目录的 `.env` 文件。
2. `ImageProctor` 的打电话、伸胳膊、转身等多数阈值仍直接写死，忽略同名配置。
3. `.env.example` 中部分默认值已经与实际运行值不同，并包含当前识别代码没有使用的站立配置。

这会造成“配置看起来改了，实际行为没变”的部署风险。

## 目标

- 让项目根目录 `.env`、系统环境变量和代码默认值形成唯一、可解释的配置链路。
- 系统环境变量优先于 `.env`，`.env` 优先于代码默认值。
- `ImageProctor` 实际使用的每一个动作阈值都来自同一个 `Settings` 实例。
- 配置类型或范围错误时在服务启动阶段明确失败，不带着错误配置运行。
- 默认配置下不改变任何一张现有测试照片的识别结果。
- `app/` 与 `deploy_split/code/app/` 保持完全一致。

## 非目标

- 不调整任何阈值数值以提高准确率。
- 不修改动作优先级、分类映射、模型或并发策略。
- 不针对固定后方 45 度机位优化识别。
- 不在本轮处理上传安全、认证或限流。

## 方案选择

采用 `pydantic-settings` 管理配置。它是 Pydantic 官方配套组件，能标准读取 `.env`、处理环境变量优先级并在启动时校验类型。相比只增加 `.env` 读取，它还能消除错误字符串静默进入业务逻辑的问题；相比自写解析器，它对引号、空格、布尔值和类型转换的处理更可靠。

新增依赖会被写入 `pyproject.toml` 和 `uv.lock`。离线服务器不需要联网安装，因为部署镜像继续包含完整 Python 环境；重新构建镜像时按锁文件安装。

## 配置结构

`Settings` 改为 `BaseSettings`，并继续以 `settings = Settings()` 暴露全局只读配置。默认读取项目根目录 `.env`，编码为 UTF-8，忽略暂时未识别的额外键，避免旧部署残留变量阻止升级。

配置优先级：

1. 进程环境变量或 Docker Compose `environment`
2. 项目根目录 `.env`
3. `Settings` 字段默认值

路径字段仍根据当前代码所在项目根目录生成，不要求用户在 `.env` 中填写绝对路径。

## 阈值单一来源

保留当前真实运行值作为默认值，包括：

- 人脸方向：左 `6`、右 `-6`、上 `6`、下 `-1`
- 打电话：腕耳距离 `0.55`、手臂角 `30`
- 伸胳膊：基础臂角 `140`、水平臂角 `155`、水平可见度 `0.4`、臂长 `1.05`、腕耳距离 `1.6`
- 手肘兜底：可见度 `0.25`、最大高度差 `0.5`、最小伸出距离 `0.7`
- 转身肩距 `0.25`
- 通用关键点可见度 `0.5`
- 多人兜底和模型池继续使用现有默认值

`PHONE_WRIST_EAR_Y_DIFF` 和三个 `STAND_*` 配置当前没有对应运行逻辑，从配置模板中删除，避免继续承诺无效开关。新增实际使用但之前未公开的阈值。

`ImageProctor` 支持注入 `Settings`，便于测试不同配置；正常服务仍使用全局 `settings`。单次接口传入的四个人脸角度参数继续拥有最高优先级，并在请求结束后恢复到服务启动配置，不污染下一次请求。

## 校验与错误处理

- 端口限制在 `1..65535`。
- 日志级别限制为 `DEBUG/INFO/WARNING/ERROR/CRITICAL`。
- 置信度和可见度限制在 `0..1`。
- 模型池和最大人体数至少为 `1`。
- 距离和角度阈值必须为非负值；左右/上下方向边界保留正负语义。
- 错误值由 Pydantic 抛出带字段名的验证错误，服务不继续启动。

## 部署与文档

- 更新 `.env.example`，使其列出的默认值与运行代码一致。
- README 明确配置优先级和“修改后必须重启服务”。
- Docker Compose 继续可用 `environment` 覆盖配置；不把开发机 `.env` 烘焙进代码。
- 同步修改分离部署副本，并用自动测试比较两份配置和识别器源码。

## 测试与验收

1. 测试 `.env` 能被读取，系统环境变量能覆盖 `.env`。
2. 测试非法数字、范围和日志级别会在构造 `Settings` 时失败。
3. 测试 `ImageProctor` 的所有运行阈值等于注入配置。
4. 测试单次人脸角度覆盖后，下一次请求恢复服务启动配置。
5. 全部单元测试和 Ruff 通过。
6. 默认配置运行 305 张主测试，逐张 `actual_action_type` 与改造前一致，基线保持 `245/305`。
7. 默认配置运行 7 张固定后方 45 度测试，逐张结果与改造前一致，基线保持 `3/7`。
8. `app/core/config.py`、`app/ml/image_proctor.py` 与分离部署副本分别完全一致。
